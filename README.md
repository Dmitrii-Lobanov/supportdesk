# SupportDesk

A customer support workspace built as a hands-on learning project with
React, TypeScript, Convex, and Clerk.

The project focuses on reactive data, backend validation, authentication,
authorization, external APIs, and reliable background processing.

## Current features

- Create tickets with a subject, description, and priority.
- Update ticket status: Open, In progress, or Resolved.
- View ticket details through a dedicated URL.
- Filter tickets by status using a database index.
- Load additional tickets with cursor-based pagination.
- Receive live updates through Convex query subscriptions.
- Sign in through Clerk.
- Restrict ticket access to approved workspace members.

## Technology

- React and TypeScript
- Vite
- Convex database and backend functions
- Clerk authentication
- React Router
- Radix Select
- ESLint and Prettier

## Local development

### Prerequisites

- A current Node.js LTS release and npm
- A Convex account
- A Clerk application configured for development

### Install dependencies

```bash
npm install
```

### Configure Convex

```bash
npx convex dev
```

Follow the prompts to create or connect a development deployment.

The CLI configures the deployment connection in `.env.local` and generates
API helpers and TypeScript types in `convex/_generated/`.

Keep this command running during backend development.

### Configure Clerk

1. Create or select a Clerk development application.
2. Enable the desired sign-in methods.
3. Activate its Convex integration.
4. Copy its Publishable Key and Frontend API URL.

Add the publishable key to `.env.local`:

```dotenv
VITE_CLERK_PUBLISHABLE_KEY=pk_test_replace_me
```

In the Convex dashboard, configure this environment variable on the
development deployment:

```text
CLERK_JWT_ISSUER_DOMAIN=https://your-instance.clerk.accounts.dev
```

`convex/auth.config.ts` uses that domain and the `convex` application
audience to configure token validation.

Do not replace the Convex connection values generated by the CLI.

### Start the frontend

In a second terminal:

```bash
npm run dev
```

Open the local URL printed by Vite.

Restart Vite after changing local environment variables.

## Environment configuration

| Variable                     | Location                         | Purpose                             |
| ---------------------------- | -------------------------------- | ----------------------------------- |
| `CONVEX_DEPLOYMENT`          | `.env.local`, managed by the CLI | Selects the development deployment  |
| `VITE_CONVEX_URL`            | `.env.local`                     | Connects the frontend to Convex     |
| `VITE_CLERK_PUBLISHABLE_KEY` | `.env.local`                     | Initializes Clerk in the browser    |
| `CLERK_JWT_ISSUER_DOMAIN`    | Convex deployment environment    | Configures the trusted token issuer |

Variables prefixed with `VITE_` are available to browser code. Never put
secret API keys in them.

`.env.example` contains placeholders only. Actual `.env.local` values
must remain outside Git.

## Approve a workspace member

Signing up creates a Clerk user but does not grant workspace access.

To approve a user:

1. Have the person sign up through SupportDesk.
2. Open their record in Clerk's Users dashboard.
3. Copy their Clerk user ID, starting with `user_`.
4. Open Functions in the matching Convex development deployment.
5. Run the internal mutation `memberships:addMember` with:

```json
{
  "clerkUserId": "user_replace_me"
}
```

Running the function again for an existing member returns the existing
membership ID.

Members share access to the workspace's tickets.

## Project structure

```text
convex/
  auth.config.ts       Token validation configuration
  schema.ts            Tables and indexes
  tickets.ts           Ticket queries and mutations
  memberships.ts       Membership lookup and provisioning
  lib/auth.ts          Authentication and membership guards
  _generated/          Generated API helpers and types

src/
  main.tsx             Clerk and Convex providers
  App.tsx              Routing and access boundaries
  components/          Forms, cards, selects, and access gates
  pages/               Ticket list and detail pages
  styles/              Shared layout and feature styles
  index.css            Global defaults and design variables
```

## Current limitations

- One shared workspace.
- Members are approved through developer tooling.
- All members have the same ticket permissions.
- Priority is selected at creation; editing it is not implemented.
- Older tickets without a priority display as Medium.
- Customer REST integration and AI assistance are not implemented yet.
- Production deployment and operational verification are pending.
